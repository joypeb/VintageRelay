# Project Structure

## 1. Top-Level Layout

Place frontend in root `frontend/` (initial proposal). Sources go under `src/`; use only the `@/*` → `src/*` alias.

```text
frontend/
├── src/
│   ├── app/              # Routing only (page, layout, error, not-found, loading)
│   ├── components/
│   │   ├── ui/           # Domain-neutral UI composed from Astryx (e.g. BottomTabBar)
│   │   └── <domain>/     # Domain components (event, item, preference, trade, suggestion)
│   ├── hooks/            # Shared hooks (useEventId, useDisclosure), not query hooks
│   ├── lib/
│   │   ├── api/          # Client, error types, domain requests/query hooks
│   │   ├── utils/        # Pure functions: cn, date/status formatting, etc.
│   │   └── env.ts        # Single environment access point
│   ├── types/            # API response/domain types
│   ├── styles/globals.css  # Astryx/Tailwind layer order and imports
│   └── astryx-themes.ts    # Generated by astryx theme add; do not edit
├── public/
└── tests/e2e/            # Playwright if needed
```

- **MUST:** keep only routing files in `app/`. Extract screen bodies to `components/<domain>/`; `page.tsx` only composes them.
- **MUST:** keep single-domain components in that domain folder. Move shared components to `components/ui/` when used by two or more domains.
- **MUST NOT:** create miscellaneous `utils.ts`/`helpers.ts` files. Split by purpose.
- **SHOULD:** colocate `*.test.ts(x)` files with their targets.

## 2. Routes

Map [screen flow](../../../flows/screen-flow-v1.md) IDs to paths below. These are initial proposals; update the mapping when flows change.

```text
src/app/
├── page.tsx                                   S0 Landing
├── events/new/page.tsx                        H1 Create event
├── join/page.tsx                              P1 Join (QR prefills ?code=)
└── events/[eventId]/
    ├── layout.tsx                             Event context, closed banner
    ├── created/page.tsx                       H2 Created/share (no bottom tabs)
    └── (tabs)/
        ├── layout.tsx                         Bottom tabs: Home | Browse | My clothes | Exchanges
        ├── page.tsx                           P2 Home
        ├── manage/page.tsx                    M1 Manage event (H3 is a modal)
        ├── browse/page.tsx                    B1 AI recommendations / B2 All (?view=all)
        ├── browse/[itemId]/page.tsx           B3 Clothing detail (I1 is a bottom sheet)
        ├── preferences/page.tsx               R1 Enter preferences
        ├── preferences/review/page.tsx        R2 Review interpretation
        ├── my-items/page.tsx                  C1 My clothes
        ├── my-items/new/page.tsx              C2 Register clothing
        ├── my-items/[itemId]/page.tsx         C4 My clothing detail
        ├── my-items/[itemId]/edit/page.tsx    C2 Edit clothing
        ├── my-items/[itemId]/analysis/page.tsx C3 Review AI analysis
        ├── trades/page.tsx                    T1 Exchanges (?tab=intents|active|confirmed|history)
        ├── trades/[tradeId]/page.tsx          T2 Pending / T3 Confirmed (branch by status)
        └── suggestions/[suggestionId]/page.tsx A1 Alternative garment suggestion
```

- **MUST:** use query parameters for segments (B1/B2, T1 tabs), not separate paths, for natural back navigation/sharing.
- **MUST:** open modals/sheets (H3, I1, confirmations) through component state, not routes.
- **MUST:** show organizer UI (M1 card, closure) only when `participant.id === event.organizerParticipantId`. This is display logic; server enforces authorization. Field casing follows the shared contract.
- **MUST NOT:** create a separate organizer app/route tree.
- **SHOULD:** centralize path builders in `lib/routes.ts`, e.g. `routes.trade(eventId, tradeId)`, rather than scattering strings.

## 3. Server and Client Components

Default to server components. Use client components (`'use client'`) for any of:

- State/effect hooks (`useState`, `useEffect`, TanStack Query).
- Event handlers (`onClick`, `onSubmit`).
- Browser APIs (`localStorage`, camera, clipboard, `navigator`).
- Session-dependent data (initial implementation fetches client-side while session design is undecided).

Rules:

- **MUST:** put `'use client'` boundaries as close to leaves as possible. Do not make entire layouts/pages client components. Use `components/<domain>/XxxScreen.tsx` for data-dependent bodies and keep `page.tsx` server-side.
- **MUST:** pass only serializable props from server to client (no functions, Date objects, or class instances).
- **MUST NOT:** handle server secrets in frontend code. Meta Model API keys, etc. belong only to backend servers.
- **SHOULD:** await Promise-based Next.js 16 `params`/`searchParams` in server components and pass strings to client components.

```tsx
// src/app/events/[eventId]/(tabs)/trades/[tradeId]/page.tsx (server component)
import { TradeDetailScreen } from '@/components/trade/TradeDetailScreen';

export default async function TradePage({
  params,
}: {
  params: Promise<{ eventId: string; tradeId: string }>;
}) {
  const { eventId, tradeId } = await params;
  return <TradeDetailScreen eventId={eventId} tradeId={tradeId} />;
}
```
